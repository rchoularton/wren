# Task & Scope Discipline — No Unapproved Tasks

Do not add tasks, scope, "optional" items, "recommendations", or follow-ups to any task list without the user's **explicit approval**.

## The rule

- Only two kinds of item belong in a task or pending list: (a) **externally-mandated work** — referee/reviewer comments, editor requirements, journal checklist items; and (b) **items the user has explicitly approved.** Nothing else.
- An idea you have for an improvement, a wording polish, a "while we're here" follow-up, a defensive tweak, or an "optional" refinement is **not a task**. You may **raise it as a question** for the user to approve or decline — but do not write it into STATUS.md, a to-do list, NOTES action items, or a "next steps" block until the user approves it.
- This covers every place tasks are recorded: `papers/{p}/STATUS.md` pending lists, NOTES action items, any "next steps", and any list you present in chat as work to do.
- **Surfacing a pre-existing stray unapproved item as if it were live is the same problem.** If you find an item already sitting in a task list that the user never approved, flag it as unapproved and offer to remove it — don't present it as agreed work.
- When in doubt whether the user approved something, it is **not** approved. Default to asking, not listing.

Agreed work is recorded; ideas are asked about one at a time (see [[one-at-a-time]]).

**Why:** The task list must mean "work we agreed to do," not "things the assistant thought might be nice."
